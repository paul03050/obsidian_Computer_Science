這篇文章的核心在於，AI 應用的主流正規劃從「寫 Prompt 的人（人機對話）」升級為「設計循環系統的人（循環工程，Loop Engineering）」。讀完這篇精彩的實戰指南後，我為你將這套思維系統化，梳理出一個核心心智模型與實戰落地架構：

## 核心心智模型：從「人機對話」到「系統設計」

傳統的 AI 使用方式是**流程輔助型**，人握著工具一回合一回合往前推。而「循環工程」則是**目標驅動型**，你定義目標、畫出邊界，讓系統自主進入「觀察—決策—行動—驗證（Observe-Decide-Act-Verify）」的內核中持續迭代，直到達成目標。

### 💡 判斷一項工作是否該做成 Loop？（三道篩子）

並非所有任務都適合做成循環，在動手前必須通過這三項檢驗：

1. **重複性**：做得足夠頻繁，設計系統的自動化成本能賺回來。
    
2. **可驗性**：定義得出明確的驗證條件，能寫成驗證子 Agent 或代碼檢查（例如：`npm run lint` 乾淨且測試全過）。**如果說不清「通過長什麼樣」，循環就不知道何時該停。**
    
3. **值得性**：產出對得起燒掉的 Token 成本（有時間與金錢的底價）。
    

## 🛠️ 自動化循環系統的「六件套」架構

一個完整的自動化系統，由以下五個部件與一個狀態層組成：

|**部件**|**角色與功能**|**實戰範例（晨間維護循環）**|
|---|---|---|
|**① 心跳 (Heartbeat)**|系統的啟動源與節奏，決定何時觸發或何時判停。|Cron 定時（每工作日 9:00）、`/goal` 判停、事件驅動（PR 打開）。|
|**② 工作區 (Worktree)**|物理隔離的執行環境，避免 AI 弄亂主線或互相污染。|`git worktree` 或獨立的分支 `claude/<slug>`。|
|**③ 技能庫 (Skill)**|把複雜、常規的 Prompt 固化成版本控制下的文件。|寫在專案中的 `SKILL.md`，定義分診、修復的標準步驟。|
|**④ 連接器 (Connector)**|讓 AI 擁有動手能力、能與外界互動的橋樑。|基於 MCP 協議，讓系統能自動開 PR、發 Slack、更新工單。|
|**⑤ 子 Agent (Sub-Agent)**|**做/檢分離**的核心。負責寫活的 Agent 不准給自己打分，由獨立、便宜的模型擔任評審。|Reviewer Agent 跑測試、對照 spec，只回 PASS/FAIL，不改動文件。|
|**⑥ 狀態文件 (State Layer)**|系統的**跨次記憶**。模型每次跑完都會忘，必須把進度寫在磁碟上。|`progress.md` 記錄：已完成、進行中、需要人（人類閘門）。|

## 📈 賺取信任的「成熟度階梯」

不要妄想一步到位讓 AI 自動合併（Auto-merge）程式碼。你應該依循以下節奏，一階一階放權：

```
[ 自治 ] -> 通過所有自動檢查，帶有安全護欄的自主執行與發布
   ▲
[ 混合 ] -> 做/檢分離：AI 起草並經過子 Agent 嚴格 Review，最後由人類簽字 (人類閘門)
   ▲
[ 唯讀 ] -> 先讓 Loop 跑「監控、總結、彙報」幾天，大白話設死限制（如不許刪除、不許回覆）
```

### 🛑 放手前的「最小安全清單」

在讓循環無人值守運作前，必須檢查這 7 個剎車與安全措施是否到位：

- **成功條件**（清晰的完成定義）
    
- **硬上限**（限制迭代次數、執行分鐘數、Token 美元預算）
    
- **隔離環境**（獨立分支或工作區）
    
- **唯讀 Checker**（不參與編寫、只負責挑錯的評審）
    
- **狀態文件**（防止系統原地打轉的記憶層）
    
- **人類閘門**（遇到高風險或失敗，立刻升級交給人類決定，絕不直推主線）
    
- **日誌通知**（夜間或無人值守時出事，隔天必須看得見追蹤）
    

## ⚠️ 循環工程的隱形代價

當系統跑得越來越快時，設計者必須警惕以下三個陷阱：

- **預算失控**：頻率是燒錢的元兇（每 5 分鐘跑一次比每小時跑一次貴 12 倍）。應學會**模型分級**（強模型規劃、便宜模型幹活）並縮短 Prompt。
    
- **理解債 (Comprehension Debt)**：AI 把你沒寫的程式碼更快送進倉庫，導致「專案裡有什麼」和你「真正理解什麼」之間的缺口越來越大。
    
- **認知投降 (Cognitive Surrender)**：因為自動化太方便，人類開始照單全收、放棄思考。
    

> **AI 槓桿 = 你的技能（Review與改進系統的能力） × 你的清晰度（定義「完成長什麼樣」的能力）**
> 
> 工具吸收了機械式的編排與調度，但永遠無法吸收兩端：**意圖**與**擔責**。
