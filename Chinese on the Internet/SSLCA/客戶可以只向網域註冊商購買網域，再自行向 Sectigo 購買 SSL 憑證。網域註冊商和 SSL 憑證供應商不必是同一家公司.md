可以，而且這是很常見的做法。**客戶可以只向網域註冊商購買網域，再自行向 Sectigo 購買 SSL 憑證。網域註冊商和 SSL 憑證供應商不必是同一家公司。**

這也是你在網路中文客服工作上很重要的觀念：網域註冊與 SSL 憑證是兩項獨立服務。

## **一、實際架構範例**

假設客戶想經營 `example.com`：

網域註冊商

**網路中文資訊**

客戶只向網路中文購買 `example.com`

取得網域使用權

憑證授權機構（CA）

**Sectigo**

客戶另外向 Sectigo 購買 SSL 憑證

完成網域控制權驗證（DCV）

網站伺服器

**客戶自己的主機或雲端平台**

安裝 SSL 憑證，啟用 HTTPS

這三個角色可以由不同業者提供服務。

## **二、客戶向 Sectigo 購買 SSL，需要什麼？**

即使網域是在網路中文註冊，客戶仍可以自行向 Sectigo 申請。

通常需要：

|項目|用途|
|---|---|
|網域名稱|例如 `example.com`|
|CSR|Certificate Signing Request，憑證簽署要求|
|Private Key|產生 CSR 時所建立的私密金鑰|
|DCV 驗證|證明客戶具有網域控制權|

Sectigo 官方說明，申請者必須擁有或獲得授權使用該網域，並完成網域控制權驗證。

docs.sectigo.com+1

**這裡有一個很重要的細節：**

客戶不需要把網域轉移到 Sectigo，也不需要把 DNS 代管服務轉移到 Sectigo。

例如，客戶可以：

- 網域註冊：網路中文
    
- DNS 代管：Cloudflare
    
- SSL 憑證：Sectigo
    
- 網站主機：AWS
    

這樣完全可以運作。

## **三、那 Sectigo 如何確認客戶真的擁有這個網域？**

這就是你之前學過的 DCV（Domain Control Validation）。

假設客戶向 Sectigo 申請 SSL，Sectigo 要求客戶新增一筆 CNAME：

|Type|Host|Target|
|---|---|---|
|CNAME|`_abc.example.com`|`_xyz.validation.sectigo.com`|

客戶必須登入**實際管理該網域 DNS 的平台**新增記錄。

例如：

- 如果 Nameserver 指向 Cloudflare，就在 Cloudflare 設定。
    
- 如果 Nameserver 指向網路中文，就在網路中文的 DNS 管理介面設定。
    

Sectigo 再透過 DNS 查詢驗證結果。

docs.sectigo.com+1

## **四、這對網路中文客服有什麼意義？**

假設有客戶打電話：

「我的網域是在你們這裡買的，但 SSL 是我自己跟 Sectigo 買的，現在 CNAME 驗證失敗，可以幫我處理嗎？」

你應該先判斷：

1. 網域是否註冊在網路中文？
    
2. 客戶目前使用哪家 DNS 代管商？
    
3. 客戶是否需要協助新增 CNAME？
    
4. CNAME 已經設定，但 Sectigo 仍然驗證失敗嗎？
    

如果 DNS 由網路中文代管，你們可能可以協助確認記錄設定；如果 DNS 在 Cloudflare，就要引導客戶到 Cloudflare 管理。

至於是否提供代客設定、技術支援或收費服務，則要依照公司內部 SOP。

## **五、最重要的觀念整理**

|客戶購買項目|是否必須向同一家公司購買？|
|---|---|
|網域註冊＋SSL|不必|
|網域註冊＋DNS 代管|不必|
|DNS 代管＋網站主機|不必|
|SSL 憑證＋網站主機|不必|

**一句話記住：網域註冊商負責網域註冊，CA 負責簽發 SSL，DNS 代管商負責 DNS 記錄，主機商負責網站運作。這些服務可以分開購買。**

補充：Sectigo 也有官方銷售及合作夥伴管道，實際購買方式與帳戶管理功能會依通路而異。

Sectigo® Official+1

你可以接著熟悉一個很實用的客服情境：**客戶在網路中文買網域、在 Cloudflare 管 DNS、在 Sectigo 買 SSL，當 CNAME 驗證失敗時，三家公司各自應負責什麼。**



客戶讓網路中文（網中）代為購買 SSL 憑證，最大的優勢是：**客戶不必自行處理與國外 CA（例如 Sectigo）之間的購買、申請及部分技術溝通，可以透過網中這個單一窗口取得服務。**

不過，這裡要區分「代購 SSL」和「SSL 安裝服務」，兩者不一定包含在同一個方案內。

## **一、客戶透過網中購買 SSL 的五個優勢**

|優勢|實際好處|
|---|---|
|1. 單一服務窗口|網域與 SSL 可以向同一家公司詢問，不必自行尋找國外 CA|
|2. 申請流程協助|可透過網中客服了解 CSR、DCV、憑證簽發等流程|
|3. 中文客服支援|遇到驗證失敗、憑證審核等問題，可以用中文溝通|
|4. 問題協調|遇到 CA 端的問題，可由網中協助確認或轉交相關窗口|
|5. 續約與管理便利|可以透過同一服務商管理網域與 SSL 訂單，減少多處管理的負擔|

這些是透過代理商或服務商購買憑證的一般優勢，實際能提供哪些協助，仍取決於網中的產品方案及內部 SOP。

## **二、直接向 Sectigo 買 vs. 透過網中買**

**方案 A：客戶直接向 Sectigo 購買**

自行處理

1. 客戶自行購買 SSL。
    
2. 自行處理 CSR、DCV 等申請流程。
    
3. 遇到驗證問題，直接向 Sectigo 或其購買通路尋求協助。
    
4. 自行管理訂單及憑證續約。
    

**方案 B：透過網路中文購買**

中文服務窗口

1. 客戶向網中購買 SSL。
    
2. 網中協助處理申請及相關流程。
    
3. 遇到問題，先向網中客服詢問。
    
4. 必要時由網中協調或轉交 CA／上游處理。
    

這裡有一點要注意：透過網中購買，不代表客戶就完全不需要懂 DNS、CSR 或 DCV。客戶仍可能需要自行設定 DNS、提供驗證資料及安裝憑證。

## **三、從客戶角度看，最有價值的是什麼？**

我認為最重要的是「問題處理的便利性」。

舉例來說：

客戶直接向 Sectigo 購買，遇到 CNAME 驗證失敗時，可能需要自己判斷：

- CNAME 是否設定錯誤？
    
- DNS 是否尚未生效？
    
- DNS 代管商是否設定有誤？
    
- 是不是 Sectigo 驗證系統的問題？
    

如果客戶透過網中購買，至少可以先向網中客服反映，由客服協助釐清問題及尋找對應的處理窗口。

但這不代表網中一定能直接修復所有問題，例如客戶使用 Cloudflare 管理 DNS，網中就未必有權限直接修改。

## **四、這對網中本身又有什麼好處？**

從商業模式來看，SSL 也是網域註冊商可以延伸銷售的服務。

**網域服務**

**Domain Registration**

網域註冊、續約、移轉

**延伸服務**

**SSL Certificate**

憑證銷售、申請協助、續約

**其他相關服務**

**DNS / Hosting**

DNS 代管、主機及網站相關服務

對網中而言，可能有幾個商業目的：

1. **增加營收來源**：除了網域註冊費，也能銷售 SSL 產品。
    
2. **提高客戶黏著度**：客戶的網域、SSL、DNS 等服務集中管理。
    
3. **交叉銷售**：原本只購買網域的客戶，未來可能購買 SSL、DNS 或主機服務。
    
4. **建立服務差異化**：不只是販售網域，也提供相關技術支援。
    

## **五、你身為客服，最值得確認的三件事**

我建議你向內部同事確認以下事項，這些會直接影響你未來怎麼回答客戶：

|問題|為什麼重要|
|---|---|
|網中代購 SSL 是否包含 CSR 產生協助？|客戶可能不知道如何產生 CSR|
|網中是否協助設定 DNS／CNAME 驗證？|這是你之前遇到的驗證失敗情境|
|網中是否提供 SSL 安裝服務？|憑證簽發與伺服器安裝是不同工作|

**最後，我想特別強調：網中代購 SSL 最核心的價值，不一定是憑證本身比較好，而是提供客戶一個中文服務及問題協調窗口。**

這也正是你作為客服的價值所在：不一定要親自解決所有技術問題，但要能判斷問題在哪個環節，以及該由誰處理。

下一步很值得把網中的 SSL 服務整理成「銷售、申請、驗證、簽發、安裝、續約」六個階段，這樣你就能完整掌握客戶從購買到使用的整個流程。
