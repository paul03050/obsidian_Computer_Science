DNSSEC（Domain Name System Security Extensions，網域名稱系統安全擴充），是一套用來驗證 DNS 回應真實性的安全機制，目的是避免使用者收到遭到偽造或竄改的 DNS 資料。

簡單來說：

> DNS 負責告訴電腦「這個網域應該連到哪裡」；DNSSEC 則負責驗證「這個答案是不是真的由正確的網域管理者發布」。

## 1. 為什麼需要 DNSSEC？

假設使用者要連線到：

`www.example.com`

一般 DNS 查詢流程：

1. 使用者輸入網址。
    
2. 電腦向 DNS 伺服器查詢 IP。
    
3. DNS 回覆：`www.example.com` 對應 `203.0.113.10`。
    
4. 電腦依照取得的 IP 連線。
    

問題在於：如果攻擊者偽造 DNS 回應，讓使用者取得錯誤的 IP，就可能把使用者導向仿冒網站。

一般 DNS：可能收到偽造的回應

使用者查詢 `www.example.com`

DNS 回覆一個 IP 位址

可能是遭到偽造的 IP

DNSSEC：增加數位簽章驗證

使用者查詢 `www.example.com`

DNS 回覆資料及數位簽章

驗證簽章，確認資料完整性與來源

## 2. DNSSEC 的運作原理

DNSSEC 主要使用非對稱式加密技術中的數位簽章，讓 DNS 資料可以被驗證。

主要涉及幾種 DNS 記錄：

|記錄類型|功能|
|---|---|
|DNSKEY|儲存公開金鑰|
|RRSIG|DNS 資料的數位簽章|
|DS|建立父層與子層網域的信任關係|
|NSEC / NSEC3|證明某筆 DNS 資料不存在|

例如：

`example.com` 啟用 DNSSEC 後，DNS 管理者會建立相關金鑰並簽署 DNS 資料，再透過 DS 記錄建立與上層網域的信任鏈。

驗證 DNS 回應的解析器，就能逐層確認簽章是否有效。

## 3. DNSSEC 和 SSL/TLS 有什麼不同？

這是你在網路中文處理網域與 SSL 客服時，很值得區分的概念。

|比較|DNSSEC|SSL/TLS 憑證|
|---|---|---|
|主要目的|驗證 DNS 資料真實性|建立加密連線並驗證伺服器身分|
|保護對象|DNS 查詢與回應|使用者與網站之間的連線|
|主要技術|DNS 數位簽章|TLS、數位憑證|
|相關機構|網域註冊管理機構、DNS 管理者|CA，例如 Sectigo、TWCA|
|是否取代對方|否|否|

可以這樣記：

- DNSSEC：確認 DNS 回答有沒有被偽造。
    
- SSL/TLS：確保連線經過加密，並驗證網站身分。
    

兩者可以同時使用，並不是二選一。

## 4. 客服工作上可能遇到什麼情況？

假設客戶反映：

「我的網域已經設定 DNSSEC，為什麼網站卻無法正常開啟？」

你可以先想到幾個可能性：

1. DNSSEC 金鑰或簽章設定不正確。
    
2. 父層網域的 DS 記錄與子層 DNSKEY 不一致。
    
3. 客戶更換 DNS 代管服務商後，沒有同步更新 DS 記錄。
    
4. DNSSEC 驗證失敗，導致支援 DNSSEC 的解析器拒絕回覆該網域的資料。
    

重要觀念

DNSSEC 設定錯誤時，可能導致網域在部分或支援 DNSSEC 驗證的解析環境中無法正常解析。這不一定代表網站主機故障，也不一定是 SSL 憑證問題。

## 5. 最後用一個例子記住

假設客戶的網站架構如下：

- 網域註冊商：網路中文
    
- DNS 代管商：Cloudflare
    
- 網站主機：AWS
    
- SSL 憑證：Sectigo
    

那麼：

|項目|負責工作|
|---|---|
|網路中文|管理網域註冊服務|
|Cloudflare|管理 DNS 記錄及 DNSSEC 相關設定|
|AWS|提供網站主機或雲端服務|
|Sectigo|核發 SSL/TLS 憑證|

最重要的是：DNSSEC 是 DNS 的安全驗證機制，不是網域、主機或 SSL 憑證本身。

你可以進一步把 DNSSEC 理解成 DNS 的「防偽驗證層」，這樣在處理網域解析異常時，就比較容易判斷問題可能出在哪個環節。
