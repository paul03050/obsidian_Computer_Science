### 這份文件在講什麼
核心背景是 **SSL 憑證效期將大幅縮短（2029 年最短僅 47 天）**，手動換證不可行，所以網路中文開發了 NC-ACME（相容 ACME 協定的自動換證系統，支援 Linux/Windows），並用這份指南幫用戶盤點環境，找出最適合的導入方式。

### 六大關鍵問題（盤點重點）
1. **純外網還是內外網都有**：純外網可用 DNS/HTTP 驗證；內網設備無法被外部 CA 連線，**必須用 DNS 驗證**。若 DNS 自管且無 API，NC-ACME 可協助在 DMZ 部署代理主機執行 DNS 驗證。
2. **除了網頁還有哪些服務需要 SSL**：API、郵件伺服器、FTPS、VPN、資料庫管理介面、網管設備後台等。
3. **DNS 怎麼管理**：這是能否自動化 DNS 驗證的關鍵。網路中文代管 DNS 最容易（整合 API）；雲端 DNS（Cloudflare 等）多數支援；**自建 DNS 若無 API 則無法自動 DNS 驗證**，建議改用 HTTP 驗證或轉移 DNS。
4. **是否有特殊網通設備掛 SSL**：負載平衡器、WAF、反向代理等。NC-ACME 預設部署到本機，外部設備需提供 SSH/SCP/API 等遠端部署方式。
5. **伺服器 OS 與版本**：Linux（Ubuntu 18.04+、Debian 10+、CentOS 7+、RHEL 8+）與 Windows Server 2016/2019/2022 完整支援；舊版有限支援；FreeBSD/macOS 未正式支援（可考慮 Docker 版）。
6. **現有憑證類型**：單域名、多域名（SAN/UCC）、Wildcard。**Wildcard 僅能用 DNS 驗證**（HTTP 無法驗證 `*.`），所以 DNS 必須有 API 或由網路中文代管。

### 與你之前所學的直接關聯
- **DNS 驗證 vs HTTP 驗證**：這份文件反覆強調的選擇邏輯，正是你之前學 DNS 記錄時的應用場景。HTTP 驗證不需改 DNS，最簡單；但內網、Wildcard、無法開放 80/443 埠時，就**必須用 DNS 驗證**，而這需要 DNS 有 API 能自動新增/刪除 **TXT 記錄**（你之前學過的 TXT 記錄設定，在這裡就是 ACME 驗證的關鍵）。
- **CNAME 與轉址的差別**：這裡的 DNS 驗證是新增 TXT 記錄，不是 CNAME 或轉址，所以不涉及你之前問的「CNAME 能不能寫 @」的問題，但同樣是在 DNS 後台操作記錄。
- **NS 與 A 記錄的層次**：文件提到「DNS 由誰管理」指的就是 NS 委派層級；而憑證部署到哪台伺服器，則涉及 A 記錄指向的目標。
