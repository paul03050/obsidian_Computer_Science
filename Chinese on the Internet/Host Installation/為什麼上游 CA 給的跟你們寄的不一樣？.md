### 一、 常見主機環境與檔案對應速查表

當客戶問「壓縮檔裡這麼多檔案，我到底要裝哪一個？」，只要先問出他的伺服器環境，就能直接對應以下清單：

  

|**伺服器 / 控制台環境**|**需要的檔案組合**|**實務操作與欄位對應說明**|
|---|---|---|
|**Plesk 控制台**|1. **Private Key**（客戶自留）<br><br>  <br>  <br><br>2. **網站憑證**（`xxx_xxx_xx.crt`）<br><br>  <br>  <br><br>3. **CA 憑證**（`My_CA_Bundle.ca-bundle`）|進入 Plesk $\rightarrow$ 網站與網域 $\rightarrow$ SSL/TLS 憑證。分別貼上或上傳「私密金鑰 (_.key)」、「憑證 (_.crt)」以及「CA 憑證 (*.ca-bundle)」三個區塊即可。|
|**Nginx**|1. **合併後的單一憑證檔**（`網站憑證` + `My_CA_Bundle`）<br><br>  <br>  <br><br>2. **Private Key**（客戶自留）|Nginx 沒有獨立的中繼憑證設定欄位。客戶必須用純文字編輯器，將**網站憑證貼在最上方**，緊接著把 **My_CA_Bundle 貼在下方**，存成一個 `.crt` 或 `.pem` 檔，再搭配私鑰載入。|
|**Apache**|1. **網站憑證**（`xxx_xxx_xx.crt`）<br><br>  <br>  <br><br>2. **Private Key**（客戶自留）<br><br>  <br>  <br><br>3. **CA Bundle**（`My_CA_Bundle.ca-bundle`）|在設定檔（`ssl.conf`）中分別指定三個路徑：<br><br>  <br>  <br><br>• `SSLCertificateFile`（網站憑證）<br><br>  <br>  <br><br>• `SSLCertificateKeyFile`（私鑰）<br><br>  <br>  <br><br>• `SSLCertificateChainFile`（CA Bundle）|
|**Windows IIS**|**包含私鑰的 PFX 檔**（`.pfx`）<br><br>  <br>  <br><br>_(或先匯入 `.p7b` 再匯出)_|IIS 無法直接匯入分開的 `.crt` 與 `.key`。若客戶當初是在該台 IIS 產生 CSR，直接用「完成憑證要求」匯入 `.crt` 或 `.p7b`；若是在別處產生 CSR，則需先用 OpenSSL 工具將 `網站憑證` + `Private Key` + `CA Bundle` 合併轉檔為 `.pfx` 後再匯入。|

### 二、 客服實務三大高頻「客訴/疑問」拆解

#### 1. 「為什麼上游 CA 給的跟你們寄的不一樣？」（如你筆記末段情境）

- **核心邏輯**：上游 CA 系統常提供「單一主憑證下載」或依不同伺服器格式分類下載；而網路中文為了方便客戶，寄送的是**包含完整信任鏈（網站憑證 + 中繼憑證 + CA Bundle）的標準整合包**。
    
- **確認方式**：只要請客戶打開兩個檔案的純文字內容，比對網站憑證（`xxx_xxx_xx.crt`）裡面的亂碼（Base64 編碼），兩者是完全一模一樣的，只是網路中文多附了中繼憑證確保相容性。
    

#### 2. 「壓縮檔裡面為什麼沒有 Private Key（私密金鑰）？」

- **核心邏輯**：基於資安原則，私密金鑰在客戶產生 CSR 的當下就只存在客戶端的主機裡，**網路中文與 CA 從頭到尾都不會經手或擁有私鑰**（這也是為什麼壓縮檔裡會特地放一份 `!PRIVATE KEY INFO!.txt`）。
    
- **處理原則**：
    
    - 請客戶回到當初產生 CSR 的那台主機或控制台（如 Plesk）尋找私鑰。
        
    - 如果客戶確定遺失且完全找不回來 $\rightarrow$ **無解，只能走「重新簽發（Reissue）」流程**（用新產生的私鑰重新生一組 CSR 並免費重發憑證）。
        

#### 3. 「我明明已經把憑證裝上去了，為什麼手機打開還是顯示不安全 / 憑證無效？」

- **原因**：電腦瀏覽器（如 Chrome）有時會自動快取或主動補齊中繼憑證，但**手機瀏覽器或 API 串接端**對憑證鏈要求極為嚴格。
    
- **結論**：這就是「只裝了網站憑證，漏裝了 `My_CA_Bundle.ca-bundle`（中繼憑證）」的典型症狀。請客戶補上 CA Bundle 並重啟網頁服務即可解決。
    

### 三、 線上快速驗證工具建議

當客戶說「我裝好了，幫我看看對不對」或「還是有錯」時，客服人員不需要盲猜，可以直接請客戶提供網址，利用免費的線上檢測工具（如 **SSL Labs** 或 **SSL Checker**）掃描：

- **看到綠色勾勾且鏈結完整**：代表安裝完全正確（若客戶端仍看到舊憑證，通常是瀏覽器快取未清或主機服務忘記 Reload/Restart）。
    
- **看到黃色驚嘆號（Chain incomplete / Missing intermediate）**：直接精準回覆客戶「您的網站憑證已生效，但漏掉了中繼憑證，請補上壓縮檔內的 `My_CA_Bundle.ca-bundle` 即可」。
