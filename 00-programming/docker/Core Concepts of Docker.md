
# 📦 Docker 核心觀念與實作筆記

## 💡 核心機制與解決的痛點

### 1. 傳統開發與部署的痛點

在沒有容器技術前，軟體開發常遇到：

- **環境不一致**：「在我電腦上可以跑，測試/生產環境就壞掉」。
    
- **新人配置耗時**：新同事加入需花數小時甚至整天設定 Node.js、Java、MySQL 等複雜環境與環境變數 。
    
- **部署重複繁瑣**：更換伺服器或擴充時，所有環境設定步驟必須重新來過 。
    

### 2. Docker 的核心解決方案

Docker 是一個用於**構建、運行與傳送**應用程式的平台 。它將應用程式及其所有依賴（程式碼、第三方庫、配置文件、運行環境）打包成一個標準化的「集裝箱」（容器）：

- **環境一次打包，到處運行**：只要開發環境成功，其他環境保證運作一致 。
    

## ⚖️ Docker 容器 vs 傳統虛擬機 (VM)

了解容器（Container）與虛擬機（VM）的根本差異，是理解 Docker 輕量化機制的關鍵 ：

|**比較項目**|**傳統虛擬機 (Virtual Machine)**|**Docker 容器 (Container)**|
|---|---|---|
|**底層架構**|需在 Guest OS 上運行完整的作業系統（核心、系統服務、圖形介面）。|**共用宿主機 (Host OS) 核心**，僅隔離應用程式及其依賴 。|
|**啟動速度**|慢（數分鐘）。|**極快（僅需數秒）** 。|
|**資源消耗**|高（佔用大量 CPU、記憶體與磁碟空間）。|**極低**（僅使用應用軟體實際需要的資源）。|
|**部署密度**|單台伺服器僅能運行數個 VM 。|單台伺服器可同時運行**上百個容器** 。|

> 💡 **核心機制提醒**：Docker 不是虛擬機，它只是宿主機上的一個隔離進程！

## 🧩 必懂三大核心概念

學習 Docker 必須釐清的三個基礎關係 ：

```
 [ Dockerfile ]  --( build )-->  [ 鏡像 Image ]  --( run )-->  [ 容器 Container ]
                                     ^
                                     | (push / pull)
                                     v
                               [ 倉庫 Registry ]
```

### 1. 鏡像 (Image)

- **定義**：一個**唯讀（Read-Only）的模板**，記載構建環境與軟體的層級指令 。
    
- **生動類比**：
    
    - **程式語言**：類比於 Java 的 **類別 (Class)** 。
        
    - **生活經驗**：類比於廚房裡的 **「食譜」** 。
        

### 2. 容器 (Container)

- **定義**：鏡像運行的**實體 (Instance)**，是一個獨立、隔離且可移植的執行環境 。
    
- **生動類比**：
    
    - **程式語言**：類比於 Java 的 **物件 (Object / Instance)** 。
        
    - **生活經驗**：類比於根據食譜做出來的 **「菜餚」** 。
        
- **特點**：同一個鏡像可以同時實例化出多個獨立運行的容器 。
    

### 3. 倉庫 (Repository / Registry)

- **定義**：集中儲存與管理鏡像的地方 。
    
- **最常見倉庫**：**Docker Hub**（公開的官方倉庫）。
    
- **作用**：允許開發者透過 `push` 上傳或 `pull` 下載鏡像，實現程式碼與環境的共享 。
    

## 🏗️ Docker 架構與運作機制

Docker 採用 **客戶端 - 伺服器 (C/S) 架構** ：

1. **Docker Client（客戶端）**：我們在終端輸入命令的地方（如 `docker run`, `docker build`）。
    
2. **Docker Daemon（守護進程 / Server）**：後台運行的守護進程，負責真正管理與建立鏡像、容器、數據卷等 。
    
3. **通信方式**：Client 與 Daemon 透過 REST API 或 Socket 進行通訊 。
    

> ⚠️ **常見踩坑**：安裝 Docker 後若未啟動後台服務（Daemon），輸入指令時會回傳無法連接 Server 的錯誤提示 。

## 🛠️ 容器化實作三步驟 (Hands-on)

將一個應用程式轉換成 Docker 容器的完整標準流程 ：

### 步驟 1：編寫 `Dockerfile`

在專案根目錄下建立名為 `Dockerfile` 的檔案（無副檔名，首字母大寫）：

Dockerfile

```
# 1. 指定基礎鏡像 (分層構建：採用輕量級 Alpine Linux + Node.js 14)
FROM node:14-alpine

# 2. 將本地檔案複製到鏡像內的指定路徑
COPY index.js /

# 3. 指定容器啟動時預設執行的指令
CMD ["node", "index.js"]
```

### 步驟 2：構建鏡像 (Build)

使用 `docker build` 命令，根據 Dockerfile 的步驟打包出鏡像 ：

Bash

```
docker build -t hello-docker .
```

- `-t hello-docker`：為鏡像命名為 `hello-docker` 。
    
- `.`：代表 Dockerfile 所在的位置（當前目錄）。
    

### 步驟 3：運行容器 (Run)

使用 `docker run` 將鏡像實例化為容器並執行 ：

Bash

```
docker run hello-docker
```

## 🚀 進階觀念與擴充工具

### 1. 數據卷 (Volumes) 與資料持久化機制

- **容器原生特性**：容器具備「無狀態性」，容器銷毀或停止時，容器內產生的資料會一併遺失 。
    
- **解決方案 (Volume)**：透過數據卷將容器內部的特定目錄**映射 (Mount)** 到宿主機的實體磁碟上，實現資料永久保存 。
    

### 2. 多容器編排工具：Docker Compose

- **解決的問題**：當應用程式變複雜（同時包含前端、後端服務、MySQL 數據庫、Redis 緩存等多個相互關聯的容器）時，手動逐一啟動非常繁瑣 。
    
- **核心機制**：
    
    - 使用單一 `docker-compose.yml` 檔案來定義一整組服務與容器間的依賴關聯 。
        
    - 僅需一條指令 `docker-compose up` 即可一次性自動安裝、建置並啟動所有關聯服務 。
        

### 3. Docker Desktop 圖形化介面

- 提供視覺化 UI，可方便查看目前系統中的鏡像列表、運行中的容器狀態、存取日誌、管理 Volume 數據卷等，非常適合初學者或偏好 GUI 操作的用戶 。
