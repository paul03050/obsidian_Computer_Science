
### 1. 定義路由

所有路由檔案都必須放在 `app` 資料夾下，且公開存取的頁面檔案名稱必須固定為小寫的 `page.tsx` 。

- **主頁 (Home page)**：`app/page.tsx`
    
- **一般路由 (`/users`)**：`app/users/page.tsx`
    
- **巢狀路由 (`/users/new`)**：`app/users/new/page.tsx`
    

> 註：若在路由資料夾內放置其他檔案（如 `test.css`），並不會被公開存取，這與舊版的 Pages Router 不同

### 2. 用戶端導頁 (Client-side Navigation)

為了避免傳統 `<a>` 標籤導致整頁重新整理、重複下載資源 ，Next.js 必須使用內建的 `Link` 元件來實作單頁應用（SPA）的導頁體驗 。

```ts
import Link from 'next/link';

// 在首頁導向 /users
<Link href="/users">Users</Link>

```
## 三、 伺服器元件 vs 用戶端元件

在 App Router 中，**`app` 目錄下的所有元件預設都是==伺服器元件 (Server Components)** 。==

### 1. 伺服器元件 (Server Components)

- **優點**：降低前端 Bundle 大小、對 SEO 友善、可安全存取金鑰、減少前端往返 API 請求 。
    
- **限制**：無法使用互動功能（如點擊事件）、無法使用 React Hooks（`useState`, `useEffect`）以及瀏覽器 API 。
    

### 2. 用戶端元件 (Client Components)

當元件需要與使用者互動時，必須在檔案的最頂端加上 **`"use client"`** 指令 。

- **提取最佳實踐**：建議將大次元件保持在伺服器端渲染，僅將需要互動的小按鈕提取成獨立的 Client Component 。
```ts
- // app/components/AddToCart.tsx
"use client"; // 宣告為用戶端元件

import React from 'react';

const AddToCart = () => {
  return (
    <button className="btn btn-primary" onClick={() => console.log('Click')}>
      Add to Cart
    </button>
  );
};

export default AddToCart;
```

## 四、 資料獲取與快取 (Data Fetching & Caching)

在伺服器元件中，可以直接將元件寫成 `async/await` 形式，並直接使用原生的 `fetch` 函式，無需使用 `useState` 或 `useEffect` 。

```ts
// app/users/page.tsx
import React from 'react';

interface User {
  id: number;
  name: string;
  email: string; // 使用 TypeScript 提供嚴格型別檢查
}

const UsersPage = async () => {
  // 伺服器端直接獲取資料
  const res = await fetch('https://jsonplaceholder.typicode.com/users');
  const users: User[] = await res.json();

  return (
    <>
      <h1>Users</h1>
      <table>
        {/* 資料渲染邏輯... */}
      </table>
    </>
  );
};
export default UsersPage;
```

### 快取行為控制 (Caching Options)

Next.js 預設會自動快取 `fetch` 的請求結果 。可透過第二個參數調整：

1. **停用快取（動態渲染）**：適用於資料頻繁變動的場景 。
    
    
    ```ts
    fetch('URL', { cache: 'no-store' });
    ```
    
2. **定時重新驗證 (ISR)**：每隔特定秒數（例如 10 秒）在背景更新一次資料 。
    
    ```ts
    fetch('URL', { next: { revalidate: 10 } });
    ```
    

## 五、 靜態與動態渲染 (Static vs Dynamic Rendering)

- **靜態渲染 (Static Rendering)**：若頁面使用的資料皆可被快取，Next.js 會在**建置時期 (Build time)** 將頁面渲染為靜態 HTML，速度極快（在 production build 時標示為 `○ Circle`） 。
- **動態渲染 (Dynamic Rendering)**：若使用了 `{ cache: 'no-store' }`，Next.js 會將頁面改為在**請求時期 (Request time)** 即時渲染（在 build 時標示為 `λ Lambda`） 。
## 六、 樣式處理 (Styling)

### 1. 全域樣式 (Global Styles)

位於 `app/globals.css`，專門放置影響整站的基礎樣式（如 `body`、網頁主題字型與顏色等），不應在此撰寫特定元件的 Class 避免檔案過於臃腫 。


### 2. CSS 模組 (CSS Modules)

用來建立具備區域作用域（Scoped）的樣式，避免 Class 名稱衝突 。


- 檔案命名約定：`[名稱].module.css` 。
    
- **注意**：因屬性會對應成 JavaScript 物件，Class 命名請使用**小駝峰式 (camelCase)**，避免使用連字號 。
    
TypeScript

```
import styles from './productCard.module.css';
<div className={styles.card}>...</div>
```
