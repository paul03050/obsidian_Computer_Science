# 📜 筆記：Obsidian Git 與 Google Drive 雙重同步衝突事件紀錄

## 🛑 問題現象（Symptom）
在使用 Obsidian Git 插件跨裝置同步筆記時，突然發生嚴重衝突，畫面跳出：
- `Conflict files - obsidian-git` 錯誤提示。
- 衝突焦點鎖定在 `.obsidian/workspace.json`（錯誤提示顯示 `Not a file: .obsidian/workspace.json`）。
- 嘗試在 Obsidian 內執行 `Pull` 或 `Commit & Push` 時，皆反覆跳出 `Pull failed`，本地與遠端（GitHub）皆陷入卡死狀態。

---

## 🔍 核心原因分析（Root Cause）

本次衝突的根本原因在於：**「將同一個包含 Git 紀錄的 Obsidian 庫（Vault），複製並放入了 Google 雲端硬碟的本地同步資料夾中。」**

這觸發了以下三個致命的底層機制衝突：

### 1. 雙重同步衝突（Double Syncing）
同一個資料夾同時被 **Git 插件** 與 **Google Drive Sync** 兩套完全不同的同步機制監控。
- **Git 的邏輯**：基於「版本提交（Commit）」與明確的時間線。
- **Google Drive 的邏輯**：基於「即時檔案覆蓋」與雲端串流鎖定。
當你在編輯筆記時，兩者在零點幾秒內搶奪同一個檔案的寫入與控制權，導致 Git 核心損毀或無法正確識別檔案類型（因而出現 `Not a file` 異常）。

### 2. `workspace.json` 頻繁變動
`.obsidian/workspace.json` 是 Obsidian 的本地暫存檔，負責紀錄目前視窗的分頁、開啟的筆記與 UI 狀態。每台裝置、每一次滑動都會造成此檔案變更。當多台裝置同時透過 Git 同步它時，極易爆發衝突。

### 3. 複製資料夾（Vault）導致的「分身衝突」
直接複製整個資料夾到 Google 雲端，也把隱藏的 `.git` 設定檔一併複製過去了。這導致兩份完全不同的本地資料夾（A-Vault 與 B-Vault）指向**同一個 GitHub 遠端倉庫**。當兩邊互相推擠、覆蓋，加上 Google Drive 的即時鎖定，最終導致遠端 GitHub 的歷史紀錄與本地徹底錯亂，無法正常進行一般的 `Pull`（合併）。

---

## 🛠️ 最終解決與復原過程（Resolution Steps）

為了解決這個死局，我們採取了「徹底切割、本地清理、強制校正」的三階段策略：

### 階段一：將複製的 B-Vault 徹底獨立化
1. **刪除 Git 軌跡**：開啟位於 Google 雲端資料夾內的 B-Vault，顯示隱藏檔案，直接刪除內部的 `.git` 隱藏資料夾，徹底與 GitHub 倉庫斷開。
2. **停用插件**：在 B-Vault 的 Obsidian 設定中，將 Obsidian Git 插件關閉或解安裝，使其轉為一個**純粹由 Google Drive 同步**的獨立筆記，一勞永逸解決雙重同步衝突。

### 階段二：清理 A-Vault 本地卡死的狀態
為了讓留在本機、專屬使用 Git 的 A-Vault 恢復正常，我們透過終端機執行了強制重設：
```bash
git reset --hard HEAD
git clean -fd
```
- **作用**：這兩行指令強制放棄了本地所有卡在衝突狀態的未提交修改，並清除了殘留的衝突暫存檔，讓本地 A-Vault 恢復到完全乾淨的狀態。

### 階段三：強制校正遠端倉庫（最終成功關鍵 ✨）
雖然本地清理乾淨了，但因為 GitHub 雲端依然留有當初衝突的錯誤紀錄，導致 Obsidian 執行 Pull 時依然會失敗。
最終我們使用**終端機強制推送（Force Push）**，以本地乾淨的狀態直接覆蓋並洗滌雲端：
```bash
git add .
git commit -m "chore: clear workspace sync"
git push origin main --force
```
- **作用**：以本地乾淨無衝突的歷史紀錄，強行覆蓋 GitHub 雲端。雲端被洗乾淨後，A-Vault 的 Git 核心終於恢復正常運作。

## 💡 未來防禦與良好習慣（Best Practices）

1. **不可混用同步工具**：一個 Obsidian 資料夾**只能二選一**使用 Git 同步或 Google Drive/iCloud 同步，絕對不能兩者並存。
2. **務必建立 `.gitignore` 檔案**：在 Git 同步的筆記根目錄下，務必建立 `.gitignore` 檔案並寫入以下內容，防止暫存檔參與同步：
   ```text
   .obsidian/workspace.json
   .obsidian/workspace-mobile.json
   ```
3. **優化插件設定**：在 Obsidian Git 插件設定中，開啟 `Pull on Startup`（啟動時自動拉取），並將 Pull Style 改為 `rebase`，能最大程度減少未來的衝突機會。
