

## 📅 12 個月、6 大階段實戰路徑

### 🔹 Phase 1 (M1–M3)：打底！真正的程式實戰

- **核心目標**：精通 Python（AI 領域的絕對標準）與 Git 版本控制 。不用死磕高深數學，但要培養對數據的敏感度 。
    
- **行動清單**：
    
    1. 寫出 5 個從零開始的小程式（計算機、檔案整理器、API 調用腳本、數據清洗器、CLI 筆記軟體）。
        
    2. 第一天起就將程式碼上傳 GitHub 。
        
    3. 每天至少寫 30 分鐘程式，戒掉「只看教學影片」的習慣 。
        

### 🔹 Phase 2 (M3–M5)：掌握 LLM API 的槓桿

- **核心目標**：告別網頁聊天介面，學會用程式碼控制 LLM 。掌握記憶管理（Conversation History）與**工具調用（Tool Use / [[Function Calling]]）** 。
    
- **行動清單**：
    
    1. 實作一個具備對話記憶功能的 Chatbot 。
        
    2. 讓模型成功調用你寫的 Function（這是通往 AI Agent 的大門） 。
        
    3. 學會處理 Prompt 的穩定性、API 限流（Rate Limits）與錯誤處理 。
        
### 🔹 Phase 3 (M5–M7)：打造 RAG 系統（作品集 1）

- **核心目標**：掌握 **RAG（檢索增強生成）**，這是目前企業最需要的技術 。讓 LLM 讀取未經訓練的企業私有文本並精準回答 。
    
- **行動清單**：
    
    1. 理解文本切塊（Chunking）、向量嵌入（Embeddings）與向量資料庫（Vector DB） 。
        
    2. 打造一個可讀取 PDF 或個人筆記的 RAG 應用 。
        
    3. 加入檢索評估（Evaluation），並部署到雲端供他人測試 。
        

### 🔹 Phase 4 (M7–M9)：打造 AI 智能體（作品集 2）

- **核心目標**：從單純回答問題的 RAG，升級到會自主規劃、使用工具完成複雜任務的 **Agent（智能體）** 。
    
- **行動清單**：
    
    1. 打造一個多步驟、會自主調用多個工具的單智能體系統 。
        
    2. 進階挑戰「多智能體協作（Multi-agent system）」，讓不同 Agent 互相審查 。
        
    3. 專注於**失敗處理（Failure Handling）**，這是區分業餘與專業的關鍵 。
        

### 🔹 Phase 5 (M9–M11)：評估、部署與 MLOps（作品集 3）

- **核心目標**：業餘者只求成功運行一次，專業工程師追求在一萬次運行中都穩定、可控且便宜 。
    
- **行動清單**：
    
    1. **建立評估套件（Evals）**：測量系統的真實度、相關性與一致性 。
        
    2. **部署與監控（MLOps）**：將系統上雲，監控流量、錯誤與 API 成本 。
        

### 🔹 Phase 6 (M11–M12)：向市場交付你自己（求職）

- **核心目標**：包裝作品集，建立公開影響力 。
    
- **行動清單**：
    
    1. 將三個核心作品寫成深入的**個案研究（Case Studies）**（包含：問題、解法、數據評估、改進空間） 。
        
    2. 「在公開場合公開建造（Build in public）」，在社群分享你的技術拆解 。
        
    3. 投遞履歷，可以從「AI 賦能的軟體工程師（AI-augmented SWE）」作為跳板 。
        

## 💡 最終總結與心態

> **"Reading about AI engineering is not becoming an AI engineer."**（閱讀 AI 理論並不會讓你成為 AI 工程師。）

在 generative AI 時代，AI 工具（如 Copilot）能幫我們寫大量程式碼，但**架構設計、系統整合、成本控制與結果評估**依然需要人類大腦 。你不是要與 AI 工具競爭，而是要學會**指揮它們** 。
